\# Требования к производительности будущей веб-версии TaskTracker



\## 1. Загрузка данных

Приложение не должно загружать большой объём данных (например, старые архивы задач), который пользователь в данный момент не использует, чтобы не перегружать оперативную память.



\## 2. Большие списки

Для отображения списков из тысяч задач необходимо обязательно использовать постраничную загрузку (pagination) или динамическую подгрузку при прокрутке.



\## 3. Клиентский JavaScript

Следует избегать длительных и сложных математических вычислений на стороне клиента (в браузере), чтобы не блокировать пользовательский интерфейс. Тяжелую логику нужно выносить на сервер.



\## 4. Медиа и вложения

Тяжёлые вложения и изображения к задачам должны использовать отложенную загрузку (lazy loading) и скачиваться только при явном открытии карточки задачи пользователем.



\## 5. Работа на слабых компьютерах

Интерфейс должен оставаться отзывчивым и работоспособным на устройствах с ограниченным объёмом оперативной памяти и слабыми процессорами.



\## 6. Автообновление данных

Приложение не должно использовать ежесекундные ресурсоемкие запросы к серверу для проверки новых задач. Следует использовать более оптимизированные подходы для снижения нагрузки на клиентский CPU.



\## 7. Рендеринг интерфейса

Количество одновременно отображаемых сложных элементов (карточек задач с комментариями и анимациями) на одном экране должно быть ограничено для предотвращения зависаний вкладки браузера.
